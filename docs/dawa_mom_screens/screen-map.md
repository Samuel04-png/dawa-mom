## Existing architecture reused

- Navigation: `GoRouter` in `lib/flutter_flow/nav/nav.dart` and the responsive shell in `lib/components/responsive`.
- Authentication: email/password, phone OTP, OAuth and Firebase migration fallback in `SupabaseAuthManager`.
- Dashboard: repository-composed snapshot in `DawaMomResponsiveDashboard`.
- Appointments: `AppointmentRepository`, `SupabaseClinicianDirectoryRepository`, appointment/result domain models, existing booking sheet, email outbox, and Dawa Clinician integration outbox.
- Cycle tracking: `PeriodTrackerService`, period settings/entries, `PeriodCycleSummary`, setup and history flows.
- Profile: `HealthProfileRepository`, profile completion and edit flows.
- Onboarding: `AppWalkthroughService` persisted to `profiles.walkthrough_completed_at`.
- Rudo: responsive preserved-state launcher and Supabase `rudo-chat` Edge Function.

## Backend guardrails

- Existing RLS policies remain enabled.
- No service-role credentials are added to Flutter.
- Existing appointment and Dawa Platform outbox architecture is preserved.
- Any learning/preferences/reward persistence is additive and owner-scoped.
- UI does not claim a voucher was issued unless the server confirms an idempotent redemption.
